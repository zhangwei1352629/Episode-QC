# Episode QC 标签库填写说明

普通项目人员如果只需要整理标签名称和判断标准，请阅读[《简易标签填写说明》](简易标签填写说明.md)。本文保留完整配置，主要面向标签管理员。

本文是 Episode QC 软件使用说明的一部分，用于指导项目管理员和标注人员编写、检查、导入及更新质检标签库。

本文以当前软件实际支持的中文简易模板为主。普通项目优先使用 YAML 简易模板；只有需要稳定英文编码、自定义严重程度、自定义处理建议或扩展填写项时，才建议使用高级模板。

## 1. 快速开始

### 1.1 获取模板

可以在 QC 页面右上角单击“下载标签模板”，也可以直接复制仓库中的模板：

- [通用中文简易模板](../app/renderer/label-template-simple.yaml)
- [洗衣机任务简易 YAML 示例](../mocap_qc_v1_design_bundle/label_templates/washing_machine_task_qc_simple.yaml)
- [洗衣机任务简易 CSV 示例](../mocap_qc_v1_design_bundle/label_templates/washing_machine_task_qc_simple.csv)

### 1.2 最简写法

一个标签库至少需要一个标签库名称，以及每个标签的英文编码和中文名称：

```yaml
标签库名称: 洗衣机任务质检标签

标签:
  - 编码: clothes_drop
    名称: 衣物掉落
  - 编码: task_incomplete
    名称: 动作未完成
  - 编码: camera_blur
    名称: 画面模糊
```

上述内容可以直接导入。软件会自动补齐以下配置：

| 省略字段 | 自动值 |
|---|---|
| 分组 | 其他 |
| 说明 | 空 |
| 范围 | 区间、时间点、整条均可用 |
| 对象 | 全局 |
| 严重程度 | 一般 |
| 处理建议 | 保留但标记 |
| 颜色 | 根据分组自动分配 |
| 启用 | 是 |

### 1.3 推荐写法

实际项目建议把判断标准、范围和对象写清楚：

```yaml
标签库名称: 洗衣机任务质检标签
版本: "1.0.0"

标签:
  - 编码: clothes_drop
    名称: 衣物掉落
    分组: 衣物处理
    说明: 衣物完全脱离手部或预期位置并向地面下落；仅调整抓握位置不标记
    范围: 时间点、区间
    对象: 画面
    严重程度: 一般
    处理建议: 待复核
    快捷键: D
    颜色: "#F97316"
```

## 2. 哪些内容可以自定义

简易模板中的字段分为“自由填写”和“限定选项”两类。

### 2.1 可以自由填写

- 标签库名称；
- 版本；
- 标签名称；
- 分组名称；
- 说明或判断标准；
- 标签编码，必须人工填写并符合英文编码规则；
- 快捷键，但不能重复或占用系统按键；
- 颜色，但必须使用 `#RRGGBB` 格式；
- 高级附加填写项的名称和选项。

### 2.2 必须从规定值中选择

| 字段 | 简易模板允许值 |
|---|---|
| 范围 | 区间、时间点、整条、全部 |
| 对象 | 全局、画面、动捕、关节、全部 |
| 严重程度 | 轻微、一般、严重 |
| 处理建议 | 保留、保留但标记、裁剪、修复、重采、废弃、待复核 |

填写无法识别的值时，导入预览会直接指出错误，并列出该字段允许填写的内容。

如果项目需要“警告、致命”等其他严重程度，或者“转人工、重新编码”等其他处理建议，需要使用高级模板统一定义，不能直接在简易模板的单个标签中随意增加。

## 3. YAML 基本格式

YAML 对缩进敏感，建议遵守以下规则：

1. 使用空格缩进，不要使用 Tab；
2. `标签:` 下每个标签以两个空格加 `-` 开始；
3. 同一标签的其他字段继续缩进四个空格；
4. 颜色必须加引号，因为 `#` 在 YAML 中表示注释；
5. 版本建议加引号，避免被当作数字；
6. 文字中包含英文冒号 `:`、井号 `#` 或其他特殊字符时，建议给整段文字加引号。

正确示例：

```yaml
标签库名称: 通用质检标签
版本: "1.0.0"

标签:
  - 编码: camera_blur
    名称: 画面模糊
    分组: 画面问题
    说明: "判断标准：连续超过1秒无法看清手部动作"
    颜色: "#8B5CF6"
```

常见错误：

```yaml
标签:
- 编码: camera_blur
  名称: 画面模糊
  颜色: #8B5CF6
```

这里的颜色会被 YAML 当成注释，最终相当于没有填写颜色。虽然部分 YAML 允许 `-` 不缩进，但为了便于人工检查，统一使用推荐格式。

## 4. 标签库级字段

### 4.1 `标签库名称`

是否必填：必填。

作用：

- 显示在 QC 页面的标签区域；
- 用来区分不同任务的标签库；
- 未填写标签库编码时，软件会根据名称生成内部编码。

示例：

```yaml
标签库名称: 洗衣机任务质检标签
```

推荐采用“任务名称 + 质检标签”的命名方式：

```yaml
标签库名称: 叠衣服任务质检标签
标签库名称: 工业装配任务质检标签
标签库名称: 通用人体动作质检标签
```

更新同一个标签库时尽量不要修改名称。名称变化可能生成新的标签库内部编码，使软件把它视为另一套标签库。

### 4.2 `版本`

是否必填：选填。

默认值：`1.0.0`。

作用：标识当前标签规范版本，便于追溯标注依据。版本不会自动改变标签行为，实际行为仍由各个标签字段决定。

```yaml
版本: "1.0.0"
```

建议的版本规则：

- 仅修改错别字或补充说明：`1.0.0` → `1.0.1`；
- 新增标签或调整判断规则：`1.0.0` → `1.1.0`；
- 大范围重构标签体系：`1.0.0` → `2.0.0`。

### 4.3 `标签库编码`

是否必填：选填。普通标注人员通常不需要填写。

作用：标签库的稳定内部标识。

```yaml
标签库编码: washing_machine_qc
```

编码必须以小写英文字母开头，只使用小写字母、数字和下划线。正式使用后不建议修改。

## 5. 标签字段

### 5.1 `名称`

是否必填：必填。

作用：

- 显示为页面中的标签按钮；
- 显示在标注列表和时间轴中；
- 可以通过名称搜索标签；
- 与人工填写的英文编码一起标识标签。

```yaml
名称: 衣物掉落
```

名称应描述一个客观现象，尽量简短明确。

推荐：

```yaml
名称: 衣物掉落
名称: 左腕追踪丢失
名称: 画面持续模糊
名称: 任务步骤遗漏
```

不推荐：

```yaml
名称: 有问题
名称: 不对
名称: 异常
名称: 其他情况
```

这些名称边界不清晰，不同标注人员容易产生不同理解。

### 5.2 `分组`

是否必填：选填。

默认值：`其他`。

作用：

- 在页面中筛选标签；
- 将同类标签组织在一起；
- 未单独指定颜色时，同一分组默认使用同一种颜色；
- 简易模板中的分组顺序按照第一次出现的顺序生成。

分组名称可以自定义，例如：

```yaml
分组: 任务执行
分组: 衣物处理
分组: 动作与安全
分组: 画面问题
分组: 动捕问题
分组: 环境与设备
```

一个任务通常控制在 3～8 个分组比较容易理解和筛选。不要为每个标签都创建一个独立分组。

### 5.3 `说明`或`判断标准`

是否必填：选填，但强烈建议填写。

下面两种写法等价：

```yaml
说明: 衣物从手中或目标位置掉落
```

```yaml
判断标准: 衣物从手中或目标位置掉落
```

作用：

- 告诉标注人员什么情况下应该使用标签；
- 鼠标悬停在标签按钮上时显示；
- 参与标签搜索；
- 作为人工标注规范，不会自动触发 AI 判断。

判断标准最好回答以下问题：

1. 能观察到什么现象？
2. 达到什么程度才算问题？
3. 哪些相似情况不应该标？
4. 应该标时间点、区间还是整条？

较好的写法：

```yaml
名称: 脚步调整较多
说明: 从拿取衣物开始到关闭洗衣机门之间，出现3次及以上与任务无直接关系的额外挪步
```

```yaml
名称: 画面模糊
说明: 连续超过1秒无法辨认手部与操作目标的接触关系；正常运动产生的轻微拖影不标记
```

```yaml
名称: 衣物掉落
说明: 衣物完全脱离手部或预期放置位置并向地面下落；仅在手中重新调整抓握不算掉落
```

不推荐：

```yaml
说明: 脚步比较多
说明: 画面不太清楚
说明: 衣物有问题
```

### 5.4 `范围`

是否必填：选填。

默认值：区间、时间点、整条均可用。

| 填写值 | 页面含义 | 标注方式 | 典型示例 |
|---|---|---|---|
| `时间点` | 某个瞬间发生的问题 | 将播放头移动到发生位置后创建标签 | 衣物掉落瞬间、碰撞瞬间 |
| `区间` | 持续一段时间的问题 | 使用 `I` 设置起点、`O` 设置终点 | 画面冻结、追踪丢失 |
| `整条` | 影响整个 Episode 的问题 | 标注自动覆盖 Episode 全长 | 动作未完成、整条文件损坏 |
| `全部` | 同时支持三种范围 | 页面三个范围下均可用 | 确实可按不同粒度记录的问题 |

多个值可以使用“、”“或”“和”、英文竖线等方式分隔：

```yaml
范围: 时间点、区间
范围: 时间点或区间
范围: 区间和整条
范围: time_point|time_range
范围: 全部
```

示例：

```yaml
- 编码: clothes_drop
  名称: 衣物掉落
  范围: 时间点、区间
```

可以只标记掉落瞬间，也可以标记从掉落到重新拾起的整个区间。

```yaml
- 编码: camera_freeze
  名称: 画面冻结
  范围: 区间
```

画面冻结通常持续一段时间，要求先设置有效起点和终点。

```yaml
- 编码: task_incomplete
  名称: 动作未完成
  范围: 整条
```

动作未完成影响整个 Episode，标注自动从 `0` 覆盖到 Episode 结束。

如果某标签只支持区间，那么页面切换到“时间点”或“整条”时，该标签不会处于可用状态。

### 5.5 `对象`

是否必填：选填。

默认值：`全局`。

当前页面实际提供四类标注对象：

| 填写值 | 页面对象 | 含义 | 典型标签 |
|---|---|---|---|
| `全局` | 全局 | 与具体相机、动捕或关节无关的任务问题 | 任务未完成、步骤遗漏 |
| `画面` | 某个具体相机 | 问题属于某一路相机画面 | 模糊、遮挡、曝光、卡顿 |
| `动捕` | 全身动作 | 问题属于整体 Mocap 或人体动作 | 身体晃动、动作不自然 |
| `关节` | 某个具体关节 | 问题属于选定的单个关节 | 左腕抖动、右膝漂移 |
| `全部` | 上述四类 | 标签支持所有当前对象 | 真正不限制对象的通用问题 |

多个对象可以组合：

```yaml
对象: 画面、动捕
对象: 动捕、关节
对象: 全局、画面
对象: 全部
```

对象在页面中的表现：

- 选择“全局”时，只能点击支持 `全局` 的标签；
- 选择 `ego_head`、`ego_chest` 等相机时，只能点击支持 `画面` 的标签；
- 选择“全身动作”时，只能点击支持 `动捕` 的标签；
- 选择“左腕”等具体关节时，只能点击支持 `关节` 的标签；
- 不支持当前对象的标签会变灰，并提示它支持哪些对象。

示例：

```yaml
- 编码: camera_blur
  名称: 画面模糊
  对象: 画面
```

标注前必须先选择发生问题的具体相机。

```yaml
- 编码: mocap_joint_jitter
  名称: 关节抖动
  对象: 动捕、关节
```

可以标记“全身动作存在抖动”，也可以选择某个具体关节后标记。

```yaml
- 编码: task_step_missing
  名称: 任务步骤遗漏
  对象: 全局
```

它描述的是任务流程问题，不应该绑定到某个相机或关节。

不建议为了方便将所有标签都写成 `对象: 全部`。这样容易把本应属于具体相机或关节的问题记录成全局问题，降低后续统计和返修定位的准确性。

### 5.6 `严重程度`

是否必填：选填。

默认值：`一般`。

| 填写值 | 建议定义 | 示例 |
|---|---|---|
| `轻微` | 不影响任务完成和主要数据使用，但值得记录 | 少量多余动作、轻微晃动 |
| `一般` | 明显降低质量，需要标记、裁剪或处理 | 短时模糊、一次重新拿取 |
| `严重` | 影响任务有效性、关键数据或整条可用性 | 动作未完成、关键数据丢失 |

```yaml
严重程度: 轻微
严重程度: 一般
严重程度: 严重
```

严重程度是创建标注时的默认值，之后可以在标注编辑窗口中调整。

建议项目在标注规范中明确统一边界，例如：

```text
轻微：不影响任务完成和主要数据使用
一般：任务完成，但部分数据需要排除或重点关注
严重：任务失败、关键数据缺失或整条不可用
```

简易模板不能填写 `非常严重`、`提示` 等任意词语。需要其他级别时应使用高级模板统一定义。

### 5.7 `处理建议`

是否必填：选填。

默认值：`保留但标记`。

| 填写值 | 含义 | 典型场景 |
|---|---|---|
| `保留` | 问题不影响使用 | 非常轻微的外观或动作差异 |
| `保留但标记` | 数据可以使用，但下游需要知晓 | 轻微碰撞、额外脚步 |
| `裁剪` | 删除问题时间段，保留其他部分 | 开头准备、短时干扰、局部卡顿 |
| `修复` | 可通过重新编码、校准或数据处理恢复 | 时间戳偏移、可恢复轨迹错误 |
| `重采` | 当前数据不满足要求，需要重新采集 | 动作未完成、关键步骤遗漏 |
| `废弃` | 整条数据不应再使用 | 文件损坏、严重安全问题 |
| `待复核` | 当前标注人员无法确定 | 边界案例、规范有歧义 |

示例：

```yaml
- 编码: camera_short_freeze
  名称: 画面短时冻结
  处理建议: 裁剪
```

```yaml
- 编码: task_incomplete
  名称: 动作未完成
  处理建议: 重采
```

```yaml
- 编码: collision_uncertain
  名称: 是否发生碰撞无法确认
  处理建议: 待复核
```

处理建议只会作为标注记录的默认建议，不会自动删除、裁剪、修复或重采数据。

### 5.8 `快捷键`

是否必填：选填。

作用：在未编辑输入框时，按对应按键快速创建标签。

```yaml
快捷键: D
```

建议使用单个英文字母或数字。同一标签库中的快捷键不能重复，并会自动转为大写。

当前系统保留按键：

```text
Space
ArrowLeft
ArrowRight
I
O
Enter
Escape
N
P
F
```

其中：

- `I`：设置区间起点；
- `O`：设置区间终点；
- `N` / `P`：下一条 / 上一条 Episode；
- `F`：相机全屏；
- `Space`：播放或暂停；
- 左右方向键：调整播放位置。

推荐示例：

```yaml
快捷键: D  # 衣物掉落，Drop
快捷键: B  # 画面模糊，Blur
快捷键: J  # 关节抖动，Jitter
```

按快捷键时，软件仍会检查当前标签范围和当前标注对象是否匹配。

### 5.9 `颜色`

是否必填：选填。

作用：显示标签按钮和时间轴标注的颜色，帮助标注人员快速区分问题类型。

格式必须为六位十六进制颜色：

```yaml
颜色: "#F97316"
```

必须给颜色加引号，因为 YAML 会把未加引号的 `#` 当成注释。

常用颜色示例：

```yaml
颜色: "#3B82F6"  # 蓝色
颜色: "#F59E0B"  # 黄色
颜色: "#F97316"  # 橙色
颜色: "#EF4444"  # 红色
颜色: "#8B5CF6"  # 紫色
颜色: "#10B981"  # 绿色
```

不填写时，软件根据分组自动分配颜色。

### 5.10 `启用`

是否必填：选填。

默认值：`true`，即启用。

```yaml
启用: true
```

暂时不想让标注人员使用某标签，但又不想删除历史定义时，可以停用：

```yaml
启用: false
```

也可以填写：

```yaml
启用: 否
启用: 停用
```

停用后标签不会出现在可用标签列表中，但已经存在的历史标注不会被删除。

### 5.11 `编码`

是否必填：必填。所有标签都必须人工填写可读、稳定的英文编码。

作用：标签在数据库、导出结果和不同标签库版本之间的稳定唯一标识。

```yaml
编码: clothes_drop
```

编码规则：

```regex
^[a-z][a-z0-9_]{2,63}$
```

也就是：

- 以小写英文字母开头；
- 只能包含小写字母、数字和下划线；
- 长度为 3～64 个字符；
- 同一标签库中不能重复。

正确示例：

```yaml
编码: clothes_drop
编码: camera_blur
编码: left_wrist_jitter
```

错误示例：

```yaml
编码: 衣物掉落
编码: Clothes-Drop
编码: 1_clothes_drop
```

不填写时，导入会直接失败，并提示“没有填写编码”。软件不再根据中文名称生成哈希编码。

标签正式投入使用后必须保持编码不变。显示名称可以修改，但编码应维持标签在新旧版本间的身份：

```yaml
编码: clothes_drop
名称: 衣物掉落
```

后续将名称优化为：

```yaml
编码: clothes_drop
名称: 衣物意外掉落
```

因为编码未变，系统仍然能识别它是原来的同一个标签。

## 6. 自定义附加填写项

如果点击某个标签后，还需要标注人员填写原因、影响对象、设备状态等信息，可以在 YAML 或 JSON 中增加 `fields`。

这是高级功能。当前页面主要通过浏览器弹窗收集附加内容，字段过多会显著降低标注效率。通常应优先把规则写进“说明”，只有确实需要结构化统计的数据才增加附加字段。

### 6.1 完整示例

```yaml
标签库名称: 洗衣机任务质检标签
版本: "1.1.0"

标签:
  - 编码: clothes_drop
    名称: 衣物掉落
    分组: 衣物处理
    范围: 时间点、区间
    对象: 画面
    严重程度: 一般
    处理建议: 待复核
    fields:
      - code: drop_reason
        name: 掉落原因
        type: select
        required: true
        options:
          - code: grip_failed
            name: 抓握失败
          - code: collision
            name: 发生碰撞
          - code: unknown
            name: 无法判断

      - code: touched_ground
        name: 是否接触地面
        type: boolean
        required: false

      - code: note
        name: 补充说明
        type: text
        required: false
```

### 6.2 附加字段公共属性

| 属性 | 是否必填 | 含义 |
|---|---:|---|
| `code` | 是 | 字段内部英文编码，同一标签内不能重复 |
| `name` | 是 | 标注人员看到的填写项名称 |
| `type` | 是 | 填写项类型 |
| `required` | 否 | 是否必填，`true` 或 `false`，默认建议写清楚 |
| `multiple` | 否 | 选择器是否记录多个值 |
| `options` | 视类型而定 | `select` 和 `multi_select` 的选项列表 |

字段 `code` 建议采用与标签编码相同的规则，例如：

```yaml
code: drop_reason
code: affected_joint
code: touched_ground
```

### 6.3 支持的字段类型

| `type` | 含义 | 当前页面表现 |
|---|---|---|
| `text` | 简短文字 | 弹出输入框 |
| `textarea` | 较长说明 | 当前版本同样使用弹出输入框 |
| `number` | 数字 | 弹出输入框并转换为数字 |
| `boolean` | 是或否 | 使用确认弹窗收集 |
| `select` | 单选 | 显示选项并要求输入一个选项编码 |
| `multi_select` | 多选 | 输入多个选项编码，以 `|` 分隔 |
| `joint_selector` | 关节选择 | 使用页面当前选择的关节 |
| `camera_selector` | 相机选择 | 使用页面当前选择的相机 |
| `stream_selector` | 数据流选择 | 使用当前对象对应的数据流 |

### 6.4 单选示例

```yaml
fields:
  - code: reason
    name: 异常原因
    type: select
    required: true
    options:
      - code: device_debug
        name: 设备调试
      - code: tracking_loss
        name: 追踪丢失
      - code: unknown
        name: 未知
```

页面会显示类似：

```text
device_debug=设备调试，tracking_loss=追踪丢失，unknown=未知
```

标注人员应输入选项编码，例如 `tracking_loss`，而不是输入中文显示名称。

### 6.5 多选示例

```yaml
fields:
  - code: affected_parts
    name: 影响部位
    type: multi_select
    required: true
    options:
      - code: left_hand
        name: 左手
      - code: right_hand
        name: 右手
      - code: body
        name: 躯干
```

选择多个值时输入：

```text
left_hand|right_hand
```

### 6.6 关节选择示例

```yaml
fields:
  - code: affected_joint
    name: 异常关节
    type: joint_selector
    required: true
    multiple: true
```

该字段不会再次弹出关节列表，而是读取标注人员在“标注对象”区域选择的当前关节。标签本身通常也应配置：

```yaml
对象: 动捕、关节
```

## 7. CSV 填写说明

使用 Excel 或其他表格软件维护标签时，可以导出 UTF-8 CSV。

### 7.1 简易 CSV 列

```csv
编码,标签名称,分组,判断标准,范围,对象,严重程度,处理建议,快捷键,颜色
clothes_drop,衣物掉落,衣物处理,衣物完全脱离手部或目标位置,时间点或区间,画面,一般,待复核,D,#F97316
body_sway,身体明显晃动,动作与安全,身体往复摆动并影响操作稳定性,区间,动捕,一般,保留但标记,S,#F59E0B
task_incomplete,动作未完成,任务执行,没有完成全部必要任务步骤,整条,全局,严重,重采,T,#DC2626
```

各列与 YAML 中的同名字段含义相同。`编码`为必填列，也可以命名为`标签编码`；`标签名称`也可以写成`名称`，`判断标准`也可以写成`说明`。

### 7.2 CSV 特别注意事项

- 标签库名称取 CSV 文件名，例如 `洗衣机任务质检标签.csv`；
- 简易 CSV 的版本默认为 `1.0.0`；
- 多个范围或对象建议用“或”“、”或英文竖线连接；
- 如果单元格中使用英文逗号，必须让表格软件正确加上 CSV 引号；
- 文件应使用 UTF-8 编码，软件也兼容 UTF-8 BOM；
- 简易 CSV 不适合维护复杂 `fields`，扩展填写项应使用 YAML 或 JSON；
- 从 Excel 导出后，建议先用文本编辑器检查中文是否乱码。

## 9. 导入和更新流程

### 9.1 页面导入

1. 在页面右上角单击“导入标签库”；
2. 输入 YAML、YML、JSON 或 CSV 文件的本机绝对路径；
3. 查看导入预览；
4. 确认新增、更新、不变和保留标签的数量；
5. 确认导入并激活；
6. 在右侧标签区域检查分组、数量、对象限制和快捷键。

### 9.2 更新标签库的建议

- 保持`标签库名称`和`标签库编码`稳定；
- 已经正式使用的标签保持`编码`稳定；
- 修改显示文字时只修改`名称`或`说明`；
- 新增标签时使用新的唯一编码；
- 不再使用的标签优先设置`启用: false`，不要直接复用旧编码表达另一个含义；
- 每次实质变更都更新`版本`；
- 导入前先查看预览，不要跳过新增、更新和保留数量的核对。

## 10. 常见错误

### 10.1 缺少标签列表

错误：

```yaml
标签库名称: 测试标签
```

正确：

```yaml
标签库名称: 测试标签
标签:
  - 编码: unnatural_motion
    名称: 动作不自然
```

### 10.2 标签没有编码

错误：

```yaml
标签:
  - 名称: 衣物掉落
```

正确：

```yaml
标签:
  - 编码: clothes_drop
    名称: 衣物掉落
```

编码不会由系统自动生成，必须人工填写可读的英文标识。

### 10.3 标签没有名称

错误：

```yaml
标签:
  - 分组: 画面问题
    范围: 区间
```

每个标签都必须填写名称。

### 10.4 范围使用自由描述

错误：

```yaml
范围: 一小会儿
```

正确：

```yaml
范围: 区间
```

持续时间阈值应该写在“说明”中，而不是写进范围字段：

```yaml
范围: 区间
说明: 连续超过1秒无法看清关键动作
```

### 10.5 对象与标签不匹配

错误示例：

```yaml
编码: left_wrist_tracking_lost
名称: 左腕追踪丢失
对象: 全局
```

更合理的写法：

```yaml
编码: left_wrist_tracking_lost
名称: 左腕追踪丢失
对象: 关节
```

### 10.6 颜色没有加引号

错误：

```yaml
颜色: #EF4444
```

正确：

```yaml
颜色: "#EF4444"
```

### 10.7 快捷键冲突

同一标签库中的两个标签不能使用相同快捷键，也不能使用 `I`、`O`、`N`、`P`、`F` 等系统按键。

### 10.8 修改了正式标签编码

修改编码可能使系统将其视为新标签。需要优化中文名称时，保留编码，只修改名称和说明。

## 11. 标签设计检查表

导入前逐项检查：

- [ ] 标签库名称能够说明适用任务；
- [ ] 版本已经填写或更新；
- [ ] 每个标签只表达一种问题；
- [ ] 每个标签都填写了可读且唯一的英文编码；
- [ ] 标签名称是客观、明确的现象；
- [ ] 高频或容易混淆的标签写了判断标准；
- [ ] 判断标准包含必要阈值和不应标记的反例；
- [ ] 范围选择符合问题的时间粒度；
- [ ] 对象正确绑定到全局、画面、动捕或关节；
- [ ] 严重程度在整个项目中使用一致；
- [ ] 处理建议符合实际后续流程；
- [ ] 快捷键没有重复或占用系统键；
- [ ] 颜色使用带引号的 `#RRGGBB`；
- [ ] 已正式使用的标签编码没有改变；
- [ ] 停用旧标签时没有删除历史标签含义；
- [ ] 导入预览中的新增、更新、不变和保留数量符合预期。

## 12. 标签设计原则

一套可长期使用的标签库应满足以下原则：

1. 标签描述客观现象，不描述个人感觉；
2. 一个标签只表达一种问题；
3. 判断标准给出可重复执行的边界；
4. 范围尽量准确，不要把所有标签都设为“全部”；
5. 对象绑定到真正发生问题的数据来源；
6. 严重程度与处理建议在项目内保持一致；
7. 高频标签可以设置快捷键；
8. 正式使用后保持内部编码稳定；
9. 附加填写项只收集确实需要结构化统计的数据；
10. 标签库变更通过版本和导入预览进行管理。

例如，不要把两类问题写成一个标签：

```yaml
编码: mixed_motion_camera_problem
名称: 动作不好且画面有问题
```

应该拆分为：

```yaml
- 编码: unnatural_motion
  名称: 动作不自然
  对象: 动捕

- 编码: camera_blur
  名称: 画面模糊
  对象: 画面
```

拆分后才能分别统计动捕质量和相机质量，也能准确定位需要返修或重采的原因。
