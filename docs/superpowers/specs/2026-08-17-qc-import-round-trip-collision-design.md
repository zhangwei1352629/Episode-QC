# QC 标注结果导入完整性与跨任务隔离设计

## 目标

修复任务目录内标注结果自动恢复的两个缺陷：

1. Episode-QC 自己导出的 `attributes_json` 和 `reviewer` 字段必须完整还原。
2. 两个任务包含相同 `annotation_id` 时，导入第二个任务不得移动、覆盖或破坏第一个任务的标注与计数。

本次不扩展到标签库自动安装、无 ID 标注、重扫覆盖策略或前端警告展示。

## 导入字段规范化

恢复单条标注前先生成规范化载荷：

- 已提供对象形式的 `attributes` 时直接使用。
- 否则读取导出格式的 `attributes_json`，要求它是可解析为 JSON 对象的字符串；格式错误作为该条标注的导入警告，不阻塞任务导入。
- `reviewer_name` 优先；缺失时兼容导出字段 `reviewer`。
- 其余字段继续复用现有 `_validate_annotation_payload` 校验。

这保证现有输入格式兼容，同时使本程序导出的结果能够无损恢复自定义属性和审核人。

## 跨任务标注 ID 隔离

写入前查询导入文件提供的 `annotation_id`：

- ID 不存在：保留原 ID 插入。
- ID 已属于当前目标 Episode：按现有幂等语义更新。
- ID 已属于其他 Episode：不得修改原记录；使用“目标 Episode ID + 原 annotation_id”生成稳定的新 ID，再写入目标 Episode。

稳定重映射使复制的结果文件可以导入多个任务，同时确保同一任务反复扫描不会重复创建标注。若极端情况下重映射 ID 已属于其他 Episode，则将该条作为冲突警告跳过，避免任何跨任务改写。

## 数据一致性

恢复函数只刷新实际写入目标 Episode 的 `annotation_count`。由于跨任务冲突不再移动旧记录，原 Episode 的标注列表与计数保持一致。

## 测试

新增两个真实往返回归测试：

1. 导出包含自定义属性和审核人的标注，再导入新工作区，验证两字段与其他核心字段保持一致。
2. 将同一结果复制到两个任务目录并依次导入，验证两个 Episode 各有一条标注、ID 彼此不同、原任务标注未被移动、计数与实际列表一致；再次扫描第二个任务仍只有一条标注。

先运行新增测试并确认在现有实现上按预期失败，再实施最小修复，最后运行工作区测试、Web 导入测试、全量测试和 `git diff --check`。
