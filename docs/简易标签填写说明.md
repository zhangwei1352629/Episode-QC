# Episode QC 简易标签填写说明

这份说明面向日常整理标签的项目人员。只需要确定“有哪些问题”和“什么情况算这个问题”，不需要配置技术参数。

## 1. 最少需要填写什么

一份标签文件只需要包含：

- `标签库名称`：这套标签用于什么任务；
- `编码`：标签的英文唯一编号；
- `名称`：标注人员在页面上看到的中文名称。

最简示例：

```yaml
标签库名称: 洗衣机任务质检标签

标签:
  - 编码: clothes_drop
    名称: 衣物掉落

  - 编码: task_incomplete
    名称: 动作未完成

  - 编码: camera_blur
    名称: 画面模糊
```

保存为 `.yaml` 文件后即可导入。其余配置由软件自动处理。

## 2. 推荐再填写四项

为了让标注人员理解一致，建议每个标签再填写：

- `分组`：把相似标签放在一起；
- `说明`：写清楚什么情况下需要标记；
- `对象`：说明问题发生在整体任务、画面、动捕还是具体关节；
- `范围`：说明问题是发生在一个瞬间、持续一段时间还是影响整条数据。

推荐示例：

```yaml
标签库名称: 洗衣机任务质检标签

标签:
  - 编码: clothes_drop
    名称: 衣物掉落
    分组: 衣物处理
    说明: 衣物完全脱离手部或预期位置并向地面下落；仅调整抓握位置不标记
    对象: 画面
    范围: 时间点、区间

  - 编码: retry_open_door
    名称: 重新打开洗衣机门
    分组: 任务执行
    说明: 首次开门没有成功，人员松手后再次尝试打开
    对象: 画面
    范围: 区间

  - 编码: body_sway
    名称: 身体明显晃动
    分组: 动作问题
    说明: 身体出现明显失稳或连续晃动；正常重心转移不标记
    对象: 动捕
    范围: 区间
```

## 3. 什么是标注对象

对象表示“这个问题具体发生在哪里”。标注前，页面需要先确定当前对象，再创建标签。

简易标签支持以下对象：

| 填写值 | 表示什么 | 适合的标签 |
|---|---|---|
| `全局` | 整个任务或整条数据，不对应某个画面或关节 | 动作未完成、流程错误、任务中断 |
| `画面` | 某一路相机画面 | 画面模糊、遮挡、衣物掉落 |
| `动捕` | 人体整体动作 | 身体晃动、动作不自然、追踪丢失 |
| `关节` | 某一个具体关节 | 手腕抖动、膝关节位置异常 |
| `全部` | 上述对象都可以使用 | 确实不限制对象的通用标签 |

填写示例：

```yaml
- 编码: task_incomplete
  名称: 动作未完成
  对象: 全局

- 编码: camera_blur
  名称: 画面模糊
  对象: 画面

- 编码: body_sway
  名称: 身体明显晃动
  对象: 动捕

- 编码: wrist_jitter
  名称: 手腕抖动
  对象: 关节
```

一个标签确实适用于多个对象时，可以使用顿号连接：

```yaml
- 编码: tracking_lost
  名称: 追踪丢失
  对象: 动捕、关节
```

使用时注意：

1. 画面问题选择 `画面`，标注时再选择具体相机；
2. 局部关节问题选择 `关节`，标注时再选择具体关节；
3. 不要为了省事把所有标签都写成 `全部`，否则后续无法准确统计问题位置；
4. 当前页面对象与标签对象不匹配时，标签会变灰，无法创建标注。

## 4. 什么是标注范围

范围表示“问题在时间上持续多久”。页面提供区间、时间点和整条三种标注方式。

| 填写值 | 表示什么 | 页面操作 | 适合的标签 |
|---|---|---|---|
| `区间` | 问题从一个时间持续到另一个时间 | 选择“区间”，使用 `I` 设置起点、`O` 设置终点，也可以在时间轴拖选 | 画面冻结、身体晃动、追踪丢失 |
| `时间点` | 问题发生在某个瞬间 | 选择“时间点”，把播放头移到发生位置后创建标签 | 衣物掉落瞬间、碰撞瞬间 |
| `整条` | 问题影响整个 Episode | 选择“整条”后创建标签，软件自动覆盖完整时长 | 动作未完成、整条文件损坏、任务流程错误 |
| `全部` | 标签可以使用上述三种方式 | 根据实际问题选择当前标注方式 | 确实可以按不同时间粒度记录的通用问题 |

最常见的填写方式：

```yaml
- 编码: camera_freeze
  名称: 画面冻结
  范围: 区间

- 编码: minor_collision
  名称: 轻微碰撞
  范围: 时间点

- 编码: task_incomplete
  名称: 动作未完成
  范围: 整条
```

一个标签可以支持多个范围，使用顿号连接：

```yaml
- 编码: clothes_drop
  名称: 衣物掉落
  范围: 时间点、区间
```

这表示既可以只标记衣物掉落的瞬间，也可以标记从掉落到重新拾起的整个过程。

选择范围时注意：

1. 有明确开始和结束、持续了一段时间的问题使用 `区间`；
2. 只关心发生时刻的问题使用 `时间点`；
3. 不需要寻找具体发生时间、问题影响整条数据时使用 `整条`；
4. 不要为了省事把所有标签都写成 `全部`，应尽量限定正确范围；
5. 当前页面范围与标签范围不匹配时，标签不会显示在当前标签列表中；
6. 省略 `范围` 时，软件默认允许区间、时间点和整条三种方式。

## 5. 编码怎么写

编码用于稳定识别标签，创建后不要随意修改。

必须遵守：

- 以小写英文字母开头；
- 只使用小写字母、数字和下划线；
- 同一份标签文件内不能重复；
- 用简短、可读的英文描述问题。

正确示例：

```text
clothes_drop
camera_blur
retry_open_door
body_sway
```

错误示例：

```text
衣物掉落
ClothesDrop
clothes-drop
01_clothes_drop
```

如果只是修改中文名称或判断标准，应保留原编码。否则软件会把它当成一个新标签。

## 6. 名称和说明怎么写

### 名称

名称应简短、明确，直接描述看到的问题。

推荐：

- 衣物掉落
- 画面模糊
- 动作未完成
- 身体明显晃动

不推荐：

- 有问题
- 异常
- 不太好
- 其他情况

### 说明

说明最好同时写清楚“需要标记”和“不需要标记”的边界。

推荐写法：

```text
衣物完全脱离手部或预期位置并向地面下落；仅调整抓握位置不标记
```

不推荐写法：

```text
衣物有问题时标记
```

编写时遵循三个原则：

1. 使用画面或动作中能直接观察到的事实；
2. 一个标签只描述一种问题；
3. 相似情况要写清楚区分方法。

## 8. 使用 CSV 填写

习惯使用表格时，也可以保存为 CSV。推荐保留以下六列：

```csv
编码,标签名称,分组,判断标准,对象,范围
clothes_drop,衣物掉落,衣物处理,衣物完全脱离手部或预期位置并向地面下落；仅调整抓握位置不标记,画面,时间点或区间
retry_open_door,重新打开洗衣机门,任务执行,首次开门没有成功，人员松手后再次尝试打开,画面,区间
camera_blur,画面模糊,画面问题,画面持续模糊无法看清关键动作；短暂运动拖影不标记,画面,区间
```

如果文字中包含英文逗号，请使用 Excel 或其他表格软件编辑并另存为 CSV，避免列错位。

## 9. 导入步骤

1. 将文件保存为 `.yaml` 或 `.csv`；
2. 打开 Episode QC；
3. 单击右上角“导入标签库”；
4. 选择或输入标签文件路径；
5. 查看校验结果，确认标签数量和名称；
6. 确认导入。

导入后重点检查：

- 标签名称是否完整显示；
- 相似标签是否放在同一分组；
- 标签对象是否与问题实际发生位置一致；
- 标签范围是否与问题持续时间一致；
- 是否有重复或含义相同的标签；
- 判断标准是否足够清楚。

## 10. 常见问题

### 提示编码格式错误

检查编码是否包含中文、大写字母、空格、短横线，或者是否以数字开头。

### YAML 无法导入

请使用空格缩进，不要使用 Tab。`标签:` 下的每个标签以两个空格加 `-` 开始：

```yaml
标签:
  - 编码: clothes_drop
    名称: 衣物掉落
```

### 同一个问题出现多个标签

保留一个含义最清楚的标签，合并说明。不要同时保留“衣物掉落”“掉衣服”“衣物落地”等重复标签。

### 修改后变成了新标签

通常是因为修改了编码。恢复原编码，只修改名称或说明后重新导入。

### 标签在页面上变灰

当前选择的页面对象与标签对象不一致。先切换到正确的整体、画面、动捕或关节对象，再创建标注；如果标签本身配置错误，则修改标签文件中的 `对象` 后重新导入。

### 标签没有出现在当前范围下

当前选择的区间、时间点或整条不在该标签支持的范围内。切换到正确范围，或者修改标签文件中的 `范围` 后重新导入。

## 11. 提交前检查

- [ ] 标签库名称能看出对应任务；
- [ ] 每个标签都有编码和中文名称；
- [ ] 编码格式正确且没有重复；
- [ ] 名称简短、没有“异常”“有问题”等模糊词；
- [ ] 说明写清楚标记条件和不标记边界；
- [ ] 每个标签的对象与问题实际发生位置一致；
- [ ] 每个标签的范围与问题实际持续时间一致；
- [ ] 相似标签已经合并或明确区分；
- [ ] 文件已在 Episode QC 中成功校验。
