# QC 自动缓存清理恢复设计

**日期：** 2026-08-13  
**状态：** 已确认，待实现  
**范围：** Episode-QC 平台缓存的安全定期清理；不部署到其他机器。

## 目标

恢复本地 `platform-cache` 的自动清理，避免完成并已同步的 QC 原始缓存长期占满工作站磁盘，同时保持后台逐 Episode 缓存、断点续传和未同步结果的安全边界。

## 删除资格

仅遍历 `ready/<job_code>`。目录必须具有可解析状态文件，且 `result_synced` 严格为 `true`、`result_synced_at` 为有效 UTC 时间、当前时间不早于该时间加 24 小时。`.partial`、`results-pending`、无状态/损坏状态、未同步、无时间戳、未来时间戳或未满 24 小时的目录一律保留。

## 调度与磁盘空间

Web 服务启动时运行一次清理，之后每小时运行一次；服务关闭时通知线程退出并等待其结束。每次清理记录来源、扫描量、删除任务、释放字节和失败项。`cache_job()` 在每个 Episode 的空间检查前执行同一清理；清理后仍不足时沿用现有磁盘不足错误，绝不提前删除安全保留期内或未同步的缓存。

后台缓存继续按 Episode 工作。自动清理只处理已经完整同步且过期的 Job，不会删除正在缓存、部分就绪、失败可恢复或有待提交结果的 Job。

## 验收

1. 启动、周期和缓存前清理均可测试，并不阻塞 Web 请求。
2. 仅过期且已同步的 ready 缓存被删除；其余目录安全保留。
3. 关闭服务时后台线程可预测地退出。
4. 自动清理与逐 Episode 缓存、恢复和结果提交的既有回归同时通过。
